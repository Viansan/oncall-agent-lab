Product experiment · retrieval → agent

同一个值守问题，为什么要升级三次解法？

这个实验不追求堆功能。它用同一组合成运行手册，比较关键词检索、可解释的轻量语义检索，以及带白名单只读工具的 Agent，观察每次升级真正解决了什么，又增加了哪些成本和风险。

01

关键词检索

低成本、低延迟、容易解释。遇到用户换一种说法时，可能直接漏掉正确手册。

02

轻量语义检索

把领域同义表达映射到概念向量，覆盖常见改写；代价是要维护领域词典，不能泛化到未知问题。

03

工具调用 Agent

根据问题选择一到两份手册、展示读取轨迹并组织答案；同时引入模型成本、延迟和错误决策风险。

先比较检索

输入同一句话，观察两个检索器为什么返回不同结果。

语义阶段是“领域概念词典 + 向量相似度”的透明离线基线，不冒充通用 Embedding 模型。

升级必须有理由

只有当上一阶段在统一问题集上暴露稳定缺口，才引入更复杂的机制。

工具必须有边界

Agent 只接受白名单文档 ID，不能列目录、拼接路径、写文件或执行命令。

轨迹不是正确性

展示“调用了什么”帮助审计，但最终仍要检查选文档、引用和处置建议。

不知道就停

知识库不覆盖的问题不强行回答；拒答和转人工是产品能力的一部分。
